# Phase 2 — UI Design Contract

> Visual and interaction contract for the accessible rich-text editor. Generated by gsd-ui-researcher from the locked Phase 2 context, Phase 1 approved UI baseline, and project requirements; approved by the independent UI checker.

---

## Phase Boundary

Phase 2 replaces the Foundation Inspector as the primary product surface with a page-neutral, centered word-processor editor for structured Ukrainian and English content. The user can place a grapheme-safe caret and directional selection, type with keyboard or IME, split and merge text blocks, apply supported formatting, and insert lists, images, simple tables, and semantic page breaks. Every mutation is available from a visible, keyboard-operable surface and is submitted through the same typed Rust command boundary.

The editor MUST NOT simulate paper pages, page numbers, printable margins, text wrapping around objects, pagination, canvas rendering, PDF preview/export/import, fillable fields, or voice capture. Those capabilities remain in later phases. The visible semantic DOM is a projection of the last accepted Rust revision; browser DOM or contenteditable mutations are never canonical state.

The Phase 1 Foundation Inspector remains available only as a development diagnostics route or a secondary disclosure. It must not occupy the primary editing layout or compete with editor actions.

## Design Principles

1. **The document is the focal point.** Application chrome stays visually quiet and the centered continuous-flow surface receives the strongest spatial emphasis.
2. **Semantic, not page-like.** Use one continuous white editing surface with block rhythm; do not draw page shadows, page edges, rulers, or pagination placeholders.
3. **State is explicit.** Selection, mixed formatting, pending composition, durable save, conflict, invalid embedded content, and destructive confirmation each have visible text and programmatic semantics.
4. **No modality privilege.** Keyboard editing, visible controls, and the future voice command layer resolve to the same command vocabulary and selection bookmark.
5. **Ukrainian first, English equal.** Ukrainian is the default interface locale. English resources use the identical key set and preserve all control names, statuses, errors, and shortcut descriptions.

## Design System

| Property | Value |
|----------|-------|
| Tool | manual — project-owned CSS custom properties and native semantic controls |
| Preset | not applicable; the existing validated shell has no components.json |
| Component library | none |
| Icon library | none; controls use visible localized text, with familiar typographic symbols only as supplemental decoration |
| Web shell | React + TypeScript, using controlled components over Rust/WASM DTOs |
| Font | application chrome: system-ui, -apple-system, "Segoe UI", Roboto, "Noto Sans", Arial, sans-serif |

This phase deliberately continues the Phase 1 project-owned token system. Do not initialize shadcn or add a registry during planning or implementation. Reuse the existing surface, text, border, focus, success, and error tokens in web/src/styles.css. New editor-only state tokens are defined below.

Visual direction: restrained professional document tool. Use flat surfaces, 1px borders, 6px radii, no decorative gradients, no floating glass effects, no illustration-led empty states, and no large shadows. A subtle sticky-boundary border may separate persistent chrome from the document; it must not resemble a paper-page shadow.

## Layout and Responsive Contract

### 1280px reference viewport

- The application shell fills the viewport. The persistent application bar is sticky at top: 0 with a minimum height of 64px and 24px horizontal padding.
- The formatting toolbar is sticky immediately below the application bar. It uses a maximum content width of 1200px, two rows of control groups when necessary, 8px gaps within a group, 16px gaps between groups, and 8px vertical padding.
- The document viewport uses 24px outer padding. The page-neutral editing surface is centered at 816px maximum width, has 48px horizontal and 48px vertical content padding, and keeps a readable default line length of at most 72ch.
- The editing surface has no fixed page height. It grows with document content and uses a minimum height of calc(100vh - persistent chrome - 48px).
- Empty gutters remain quiet background. There is no permanent inspector sidebar. Diagnostics open in a secondary disclosure or dedicated development route.
- The status region remains visible in the application bar and is also announced through its live region; do not add a floating toast that covers document content.

### 320px reference viewport

- The application bar uses 16px padding and wraps into an identity row, a durability-status row, and a full-width undo/redo row. The full document title remains programmatically available; visual overflow uses one-line ellipsis.
- Undo and redo remain visible labeled 44px controls. Neither moves into an unlabeled icon menu.
- The formatting toolbar is sticky below the wrapped application bar and uses 8px padding. The block-style selector occupies the full row. The next row exposes visible buttons “Жирний”, “Курсив”, and “Підкреслення”. A third row exposes “Ще форматування” and “Вставити”.
- “Ще форматування” opens a full-width anchored panel containing font, size, text color, language, alignment, paragraph spacing, and list controls in source order. It is not a destructive modal. Escape closes it and restores the logical editor selection.
- The document viewport has 8px outer padding. The editing surface is full width with 16px content padding, no horizontal page scroll, and a minimum tap target of 44px for all controls.
- Tables may scroll horizontally inside their own labeled container when their intrinsic minimum width exceeds the surface. The application shell and document text must never cause horizontal viewport scrolling.
- Embedded-block action bars wrap below the selected object; no action is hidden solely because of width.

### Intermediate widths

- From 480px through 767px, use 16px outer padding and 24px editor padding; toolbar groups wrap only at group boundaries.
- From 768px through 1279px, keep the full toolbar vocabulary visible and allow two rows. The editing surface width is min(816px, 100% - 48px).
- Responsive changes alter arrangement only. Control names, source order, command availability, keyboard reachability, and live-region behavior remain identical.

## Interaction Contract

### Document lifecycle and durability

1. If no durable document exists, the primary action is “Створити документ”. If a durable document exists, “Відкрити останній документ” is primary and creation is secondary.
2. A newly created or opened document always contains at least one editable paragraph. An otherwise empty document therefore shows the blank-paragraph empty state inside the editor rather than an empty application.
3. Every mutation submits the displayed base revision and stable selection endpoints. The UI publishes document content, selection, formatting state, undo/redo availability, audit summary, and revision only from the accepted Rust result.
4. “Збережено” is shown only after the IndexedDB write completes and the recovered record set has been revalidated. During the durable transaction, show “Зберігаємо зміни…” and never imply completion.
5. A failed or stale command retains the prior accepted document, selection, formatting state, revision, and history. The failure is not silently snapped, rebased, retried, or redirected.

### Caret, selection, and focus

1. The editor exposes one directional selection. Its anchor and focus map only to stable node IDs, UTF-16 offsets, and affinity. DOM paths, absolute indices, pixel coordinates, and DOM Range objects remain view-local.
2. Pointer placement, Left/Right, Shift+Left/Right, Home/End, selection extension, Backspace, and Delete resolve only to Rust-approved grapheme boundaries. A malformed target returns a stable alert and leaves the selection unchanged.
3. The visible caret is a 2px accent line. Selected text uses the selection token and retains at least 4.5:1 text contrast. Selection direction is not inferred from visual ordering.
4. Clicking or tabbing into a toolbar control stores the logical selection bookmark. Applying or canceling the control restores focus to the editor and restores that selection if its base revision is still current.
5. If another accepted revision invalidates the bookmark, the toolbar action is rejected, the document is unchanged, focus returns to the editor, and the stale-selection error is announced.
6. Atomic blocks receive a 3px accent outline and a visible block action bar when selected. Delete/Backspace on a selected image or table opens the same confirmation used by its visible remove control. A selected page break may be removed immediately because it contains no user data; the action remains undoable.
7. Do not move focus for ordinary success or error announcements. Dialog validation moves focus to the first invalid field. Activating `editor.image.insert.cancel` or pressing Escape in ImageInsertDialog closes it without insertion; activating `editor.table.insert.cancel` or pressing Escape in TableInsertDialog closes it without insertion. Either path restores the originating selection and editor focus.

### Keyboard, text input, IME, and paste

1. Handle text input through beforeinput and composition events; browser mutations are intercepted or reconciled as transient UI only. Exactly one compositionend creates one atomic command. compositioncancel creates no command.
2. During composition, render the candidate text inline with a 2px dotted composition underline and show the non-live informational label “Введення через IME…”. Do not announce every interim candidate.
3. Formatting, structural, insert, undo, and redo commands that could change the composition base are disabled while composition is active. Escape cancels composition without a mutation.
4. If the accepted base revision changes, discard the transient composition and show the exact invalidation alert from the copy contract. Never relocate candidate text.
5. Plain-text paste uses the same insertion command as typed text. If the clipboard includes HTML, import text/plain only and announce the exact plain-text paste notice once.
6. Core shortcuts: Ctrl/Cmd+Z Undo; Ctrl/Cmd+Shift+Z Redo; Ctrl/Cmd+B Bold; Ctrl/Cmd+I Italic; Ctrl/Cmd+U Underline; Ctrl/Cmd+Shift+7 numbered list; Ctrl/Cmd+Shift+8 bulleted list. Do not intercept a shortcut while event.isComposing is true.
7. Tab traverses application controls. Inside a table it moves to the next cell; Shift+Tab moves to the previous cell. At the first or last cell it leaves the table rather than silently adding structure.

### Structural transformations

1. Enter in the middle of a paragraph splits it and preserves compatible block style and inline marks.
2. Enter in the middle of a heading preserves heading semantics on both blocks. Enter at the end of a heading creates a body paragraph.
3. Enter in a non-empty list item creates a sibling item. Enter in an empty list item exits the list and creates a body paragraph.
4. Backspace/Delete at a compatible text-block boundary merges blocks while preserving logical order and inline marks. Images, tables, and page breaks never merge implicitly.
5. Removing the last editable block immediately produces a new empty paragraph in the same transaction.
6. Unsupported structural combinations disable their visible action and expose a concise reason through aria-describedby; they never submit a speculative command.

### Formatting state

1. A collapsed selection applies inline controls to pending typing attributes. The active state remains visible until the caret moves to text with a different computed mark set.
2. A range with a consistent value shows that value. A mixed range shows an explicit “Змішані значення” label and aria-pressed=mixed for toggle buttons.
3. Choosing a value for a mixed range applies that single value to the entire range in one transaction.
4. Block attributes apply to every selected compatible block. Atomic blocks are excluded and reported rather than silently reformatted.
5. Toolbar state updates only after a successful core result; no optimistic pressed state survives rejection.

### Embedded blocks

1. Image insertion accepts only bounded PNG and JPEG input. The capability-provided byte and decoded-pixel limits are displayed next to the file field and repeated in the validation error.
2. “Вставити зображення” remains disabled until decoding succeeds and the user supplies useful alt text or explicitly selects “Декоративне зображення”. Decorative images store an empty alt value and show a visible decorative badge in edit mode.
3. Image load/decode failure shows a labeled placeholder with “Замінити файл”; it never removes the semantic image node silently.
4. Table insertion defaults to 2 rows × 2 columns. Row/column fields use min 1 and the core-advertised maximum. The optional header row produces native column headers.
5. Table cell navigation follows logical row-major order. Visible row/column controls operate on the cell containing the logical selection and preserve focus in the nearest surviving cell after success.
6. Page breaks render as labeled semantic separators. Inserting one places an editable paragraph after it in the same transaction and moves the caret there.

### Control interaction states

- **Rest:** white surface, neutral 1px control border, primary text.
- **Hover:** stronger neutral border; do not change geometry.
- **Pressed/open:** light accent tint and inset 1px accent border.
- **Selected formatting:** light accent tint, accent border, visible check/state text where space permits, and aria-pressed=true.
- **Mixed formatting:** neutral striped or dash marker plus text “Змішані значення”; aria-pressed=mixed. Do not use half-opacity alone.
- **Focus-visible:** 3px solid accent outline with 2px offset.
- **Disabled:** 55% visual opacity plus native disabled semantics and an adjacent/associated reason when the cause is contextual.
- **Pending:** initiating control disabled, label changed to an exact pending verb, and static text progress. No spinner-only state.
- **Error:** retain prior control value, place inline error text below the owning control, and announce the atomic error once.

## Accessibility and Localization

- The visible document projection uses native p, h1–h6, ol, ul, li, figure, img, table, thead, tbody, th, td, and hr/separator semantics inside one region labeled “Редактор документа”. Do not replace this with canvas, an ARIA-only replica, or a flat textbox that hides document structure.
- The controlled input host and visible semantic projection expose one document text copy to assistive technology. Transient composition text is marked as composing and is not duplicated in a second live region.
- The document root carries its document-language metadata. Inline Ukrainian and English ranges use lang attributes independently of interface locale. Interface chrome uses the active UI locale.
- The toolbar is labeled “Форматування”. Native selects retain visible labels. Toggle buttons expose aria-pressed false, true, or mixed. Menus/disclosures expose aria-expanded and aria-controls.
- Dialogs have a visible heading, description, focus containment, Escape dismissal, and focus restoration to the originating selection. ImageInsertDialog exposes the localized `editor.image.insert.cancel` action, and TableInsertDialog exposes the localized `editor.table.insert.cancel` action; Escape invokes the same object-specific action as the visible control.
