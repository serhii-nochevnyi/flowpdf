## Security Profile

- ASVS level: L1
- Blocking threshold: high

## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser/TypeScript → WASM | Commands and stored record DTOs are untrusted inputs to Rust. |
| Rust persistence DTOs → IndexedDB → Rust recovery | Physical storage can be partial, corrupt, or tampered despite same-origin locality. |
| Audit DTO → DOM/accessibility tree | Over-broad diagnostics can disclose semantic content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-01 | Tampering | WASM command boundary | high | mitigate | Task 01-02-01 uses typed decode, revision validation, immutable Rust application, and stable failure DTOs; JavaScript receives no mutable handle. |
| T-02-02 | Tampering / Denial of Service | IndexedDB commit and reload | high | mitigate | Task 01-02-01 commits related records in one short transaction, acknowledges on completion, and revalidates canonical hash/revision in Rust after reload. |
| T-02-03 | Information Disclosure | Inspector audit/provenance | high | mitigate | Rust constructs an allowlisted audit DTO and Task 01-02-01/02 renders only safe fields via text APIs. |
| T-02-04 | Elevation of Privilege | Local inspector controls | low | accept | There is no identity, authorization, backend, or privileged operation in scope; controls operate only on the local sample through the same command boundary. |
</threat_model>
