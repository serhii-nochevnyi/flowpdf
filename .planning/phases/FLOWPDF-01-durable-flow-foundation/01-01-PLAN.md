## Trust Boundaries

| Boundary | Description |
|---|---|
| Internet registries/repos → local files/toolchains | All metadata, archives, installers, and dependency identities are untrusted until verified. |
| Lockfiles → executable builds | A drifted origin or integrity field can redirect future installs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-SC | Tampering | Cargo/npm/rustup/browser installs | high | mitigate | Task 01-01-01 verifies official registry metadata, checksums/integrity, and allowlisted repositories before Task 01-01-02/03; lock verifier blocks alternate origins. |
| T-01-02 | Spoofing | Rust installer/toolchain | high | mitigate | Fetch only the official static Rust host and verify the published SHA-256 before executing rustup-init; pin and report the resulting exact toolchain. |
| T-01-03 | Denial of Service | Registry or repository unavailable | medium | accept | The phase performs no partial install; bounded timeout writes a specific blocker and preserves the untouched workspace, so availability loss cannot become silent trust. |
| T-01-04 | Information Disclosure | Provenance diagnostics | low | accept | Reports contain public package metadata and local tool versions only; no tokens, environment dumps, or credentials are recorded. |
</threat_model>
